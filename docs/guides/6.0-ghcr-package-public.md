# Make the transcoder GHCR package public (Sprint 6.0, Phase B — one-time)

The Sprint 6.0 workflow (`.github/workflows/deploy-transcoder-dev.yml`) builds the transcoder image and pushes it to **GitHub Container Registry** at `ghcr.io/klundt-org/slaylist-transcoder` (D49). The **push** needs nothing from you — Actions authenticates with its automatic `GITHUB_TOKEN`.

But the **first** push creates the package as **private** (GHCR's default), and our dev Container App pulls the image with **no credential** (that's the whole point of a public image — D49). A private package can't be pulled anonymously, so the Container App update would fail with an image-pull error until you flip the package to **Public**. This is a **one-time** toggle — GHCR remembers the visibility across all future pushes.

## When to do this

**After** the workflow's build+push step has succeeded at least once (so the package exists), and **before** (or right when) the `az containerapp update` step runs. If the very first run fails only on the Container App update with an auth/pull error, that's expected — do this toggle, then re-run the workflow.

## Prerequisite — allow public packages at the org level (one-time, org-wide)

**Gotcha found on the first live run (Sprint 6.0):** `klundt-org` shipped with **public packages disabled org-wide**, so the per-package *Change visibility → Public* control below was **greyed out / "disabled in the org."** The org policy must be loosened first (org owner only):

1. Go to **https://github.com/organizations/klundt-org/settings/packages**
2. Under **Package creation** / package-visibility policy, enable **Public** as an allowed visibility (it was Private/Internal-only by default).
3. Save. The per-package toggle below is now available.

This is itself one-time and org-wide — once enabled, every package (including the Epic 9 prod image) can be made public. If org policy should *not* be loosened, keep the image private instead and give the Container App a pull credential (GHCR registry secret) or switch to **ACR** with its Managed Identity (D49's documented private-image upgrade path).

## Steps (GitHub UI)

1. Go to the org's packages: **https://github.com/orgs/klundt-org/packages**
   (or the repo → right sidebar → **Packages** → `slaylist-transcoder`).
2. Click the **`slaylist-transcoder`** package.
3. **Package settings** (right side) → scroll to the **Danger Zone**.
4. **Change visibility** → choose **Public** → type the package name to confirm.
5. While on the package settings, confirm **Manage Actions access** lists the `SLAYList` repo with **Write** (it's added automatically on first push; this is what lets future workflow runs keep pushing).

## Verify

- The package page header shows **Public**.
- Anyone (including the credential-free Container App) can now pull:
  ```
  docker pull ghcr.io/klundt-org/slaylist-transcoder:dev
  ```
  (You don't need to run this — it's just what "public" now permits.)

## Why not automate this in the workflow?

Changing package visibility needs a token with `admin:packages` scope; the workflow's automatic `GITHUB_TOKEN` deliberately does **not** carry it (least privilege). Rather than introduce a stored admin PAT just to flip one setting once, this stays a one-time human toggle — consistent with the project's "no long-lived secrets" posture (D30/D49).

## Prod (Epic 9)

The prod image pipeline will create its own package (or reuse this one — decided at Epic 9). If it's a new package, repeat this toggle once for it. Same public-GHCR posture unless a private image is wanted then (→ ACR per D49).
